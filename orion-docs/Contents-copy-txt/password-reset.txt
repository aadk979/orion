---
title: Password reset
description: The emailed-code reset flow, its IP binding, and what happens to live sessions.
---

A two-step, emailed-code flow. Both endpoints are unauthenticated and reachable
with a `NO_AUTH_BEARER`.

```http
POST /alpine/api/v1/action/initiate-password-reset
POST /alpine/api/v1/action/complete-password-reset
```

Requires SMTP credentials — there is no reset without a way to send the code.

## Initiate

Creates a `password_reset_requests` row and emails a 6-digit code. The row
records the requesting IP and a real, app-supplied expiry (not just a
garbage-collection hint), and the browser receives a `passwordResetRequestId`
cookie valid for 15 minutes.

## Complete

Verifies the code and sets the new password.

Two properties are worth calling out:

<Callout type="warning" title="The reset is IP-bound">
Completing from a different network than the one that requested it returns
`ACCOUNT-SIGNIN::PASSWORD-RESET-IP-MISMATCH::A::p`. This stops a code intercepted
in transit from being used elsewhere — but it does mean a user who requests on
mobile data and completes on Wi-Fi has to start over. Factor that into your
support copy.
</Callout>

<Callout type="warning" title="The attempt ceiling destroys the request">
`attempts` and `max_attempts` are enforced per record. Exceeding the ceiling
returns `ACC-PASSWORD-RESET-ATTEMPTS-EXCEEDED` (HTTP 429) and the reset request
is **cancelled**, not merely rejected — a guessed code can never be retried
against it. Both endpoints are charged cost 5 by the rate limiter.
</Callout>

## Live sessions after a reset

A successful reset moves the user's `sessions_valid_from` watermark forward.
Everything issued before that instant is dead in a single comparison — including
stateless tier-1 tokens, which have no rows to delete.

That is the behaviour you want: resetting a password because it was compromised
should sign the attacker out too.

## The email template

`lib/Utils/Mail/email_templates/passwordReset.txt` is the shipped body. It is a
plain-text template rendered by `mailConstructor.js`. Edit it in your fork if you
need different copy or branding.

## Failure codes

| Code | Meaning |
| --- | --- |
| `ACC-PASSWORD-RESET-ATTEMPTS-EXCEEDED` | Too many wrong codes; the request was cancelled |
| `ACCOUNT-SIGNIN::PASSWORD-RESET-IP-MISMATCH::A::p` | Completion came from a different network |
| `DATA-VALIDATION::INVALID-DATA::A::p` | The packet failed schema validation |

## Administrative reset

If an operator needs to set a password directly, without the emailed-code flow,
use the server-side API:

```js
import { userControl } from '@aadharsh/orion-alpine-x934x';

await userControl.updateUserPassword(uid, newPassword);
```

This is audited like every other `userControl` call. See
[User administration](/versions/alpine/docs/guides/user-administration).
