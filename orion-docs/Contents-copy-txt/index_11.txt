---
title: Orion Documentation
description: Orion is a self-hosted authentication framework for Node.js, plus a cluster control plane and a PBAC-governed admin plane for operating a fleet of auth nodes.
---

Orion is authentication you run yourself. An **Orion-core** node is an Express
application your service embeds: it owns signup, sign-in, sessions, tokens,
passkeys, TOTP, device authorization, OAuth, password reset, abuse defense, and a
tamper-evident audit trail. **Orion-Orchestrator** supervises a fleet of those
nodes and exposes a policy-governed admin plane — web panel, JSON API, and the
`orionctl` CLI. **R_Sync** is the encrypted machine-to-machine transport the
control plane rides on. A **browser SDK** is what your front end talks to.

Nothing here is a hosted service. You provision Postgres, you hold the signing
keys, and every request is served by a process you control.

## What is in the box

| Package | Package name | Version | What it is |
| --- | --- | --- | --- |
| Orion-core | `@aadharsh/orion-alpine-x934x` | 1.0.6 · Beta | The auth framework your Node/Express app embeds |
| Orion-Orchestrator | `orion-orch` | 1.1.0 · Stable | Cluster control plane + PBAC system-admin plane |
| R_Sync | `r-sync` | 1.0.0 · Stable | Encrypted M2M transport under the control plane |
| Client SDK | `@aadharsh/orion-client` | 1.0.6 | Browser SDK, built to `dist/orion.beta.sdk.js` |

<Callout type="info" title="Beta status">
Orion-core reports `__Status__: 'Beta'`. The surface documented here is what the
current build does, but it is not frozen — pin the version you deploy and
re-read these pages before upgrading. Edition 001 has not been issued yet; see
the [edition timeline](/versions/alpine) for what that means in practice.
</Callout>

## The shape of a deployment

<Architecture />

Every auth node is identical and keeps no per-request state of its own. Nodes
share durable state through Postgres and share JWT signing keys through Redis, so
a token minted by one node validates on any other. The orchestrator is optional
for a single node; it is what turns several nodes into a cluster — health,
consensus, fleet-wide commands, and governed human access.
